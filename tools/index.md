# Tools

<p class="lead">Tool documentation defines what a model or agent may invoke, the public inputs and outputs, permission boundaries, and observable failure behavior.</p>

## Tool contract

Each published tool page should answer four questions: what the tool does, what data it accepts, what authority it has, and how callers should handle failures or unavailable capabilities.

## Safety and permissions

A tool being documented does not imply unrestricted access. User authorization, product eligibility, workspace policy, and service availability may still gate execution.

## Publication status

Detailed tool schemas will be added as production tool contracts are selected for public documentation.
